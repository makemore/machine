mach

One command to spin up a dev machine — local VM or cloud server. Linux, macOS, or Windows.

click to copy curl -fsSL https://makemore.github.io/machine/install.sh | sh

What it does

📄

Declarative config

Define your machine in a Machinefile — OS, resources, packages, repos, commands. Commit it to your repo.

🖥️

Any OS

Linux, macOS, or Windows VMs. Same workflow, same commands, same config format.

☁️

Local or cloud

Run locally with Lima, Tart, or QEMU. Or deploy to Hetzner, DigitalOcean, or GCP. Change one line.

⚡

One command

mach up — creates the machine, installs packages, clones repos, runs your commands. Done.

Quick start

# Install mach
curl -fsSL https://makemore.github.io/machine/install.sh | sh

# Create a Machinefile
cat > Machinefile << 'EOF'
name: dev
os: linux
resources:
  cpu: 4
  memory: 8gb
setup:
  - install: git curl build-essential
  - clone:
      repo: https://github.com/your-org/your-repo
      dest: ~/project
run:
  - cmd: cd ~/project && make build
EOF

# Spin it up
mach up

# SSH in
mach ssh

# Or deploy to the cloud instead
mach -f Machinefile.hetzner up

Full Machinefile spec

name: my-vm
os: linux
provider: hetzner          # local, hetzner, digitalocean, gcp
region: eu-central         # friendly names mapped to provider slugs
cloud_init: ./cloud-init.yaml  # raw user-data for cloud providers

ssh_keys:                  # multi-user SSH access
  - username: chris
    public_key: "ssh-ed25519 AAAA..."
  - username: alice
    public_key: "ssh-ed25519 AAAA..."

env:                       # injected into /etc/environment
  API_KEY: "sk-..."
  NODE_ENV: "production"

resources:
  cpu: 4
  memory: 8gb

setup:
  - install: docker.io git curl
  - script: ./scripts/startup.sh  # copy & run a local script
  - clone:
      repo: https://github.com/org/repo
      dest: ~/app
  - cmd: cd ~/app && make build

run:
  - cmd: cd ~/app && make serve

expose:                    # firewall rules on Hetzner/DO
  - 3000
  - 8080

Commands

CommandDescription
mach upCreate, provision, and start the machine
mach downStop the machine
mach destroyDelete the machine (stops cloud billing)
mach sshSSH into the machine
mach statusShow machine details
mach listList all machines across all providers
mach doctorCheck dependencies

All commands accept -f <file> for Machinefile path, --json for machine-readable output, and --state-file for CI/CD state persistence.

JSON output

Use --json for CI/CD integration. Every command returns structured data:

$ mach -f Machinefile.hetzner up --json
{"name":"dev","ip":"1.2.3.4","status":"running","provider":"hetzner","region":"fsn1-dc14","cpus":4,"memory_mb":8192,"disk_gb":80,"os":"linux","type":"cax21"}

$ mach list --json
[{"name":"dev","status":"running","os":"hetzner","cpus":"4","memory":"8 GB"},{"name":"mac-dev","status":"stopped","os":"macos"}]

Features

🔑

Multi-user SSH

ssh_keys: with username + public_key pairs. Keys auto-uploaded to cloud providers.

🔥

Firewall rules

expose: ports automatically create firewall rules on Hetzner and DigitalOcean.

📜

Scripts & cloud-init

- script: ./startup.sh copies and runs local scripts. cloud_init: for raw user-data.

🔧

Environment variables

env: block injects vars into /etc/environment — API keys, config, secrets.

📋

JSON output

--json flag on all commands for CI/CD pipelines. Returns IP, status, provider.

💾

State file

Persists machine info for idempotent CI runs. --state-file for custom paths.
